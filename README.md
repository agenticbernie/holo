# Holo

Holo is a Cloudflare Workers backend and Astro frontend for fashion e-commerce SKU-KOC recommendations and reproducible synthetic datasets.

## Architecture

The monorepo follows Clean Architecture:

- `apps/api`: Hono Worker, OpenAPI routes, request middleware, composition, and Queue consumer.
- `packages/domain`: framework-independent entities, validation rules, ports, scoring policy, and dataset invariants.
- `packages/application`: use cases and orchestration.
- `packages/contracts`: Zod request and response schemas used by OpenAPI.
- `packages/database`: D1 migrations and repository adapters. Runtime SQL is confined here.
- `packages/storage`: Effect-based R2 artifact adapter.
- `packages/llm-client`: Effect-based Kimi API client for semantic fields only.
- `packages/synthetic-generator`: seeded deterministic numeric simulation and semantic fallback.
- `packages/config`: runtime environment validation.
- `apps/web`: Astro SSR frontend with React islands and Astryx UI.
- `packages/api-client`: centralized Zod-validated browser API client.

## Dataset Generation

Default parameters are 200 SKUs, 80 KOCs, 200 campaigns, 3,000 interactions, cold-start rate `0.25`, and seed `20260806`. Safety limits are enforced by Zod and domain validation.

Numeric outcomes are generated by deterministic seeded code. The generator includes successful, failed, high-view-low-conversion, low-view-high-conversion, inventory shortage, seasonality, and promotion scenarios. It enforces `revenue = orders * sellingPrice`, `orders <= clicks <= views`, non-negative stock, valid enums, and unique IDs.

Kimi is used only for semantic text and tags. When Kimi is absent, unavailable, or returns invalid data, deterministic semantic templates are used. Structured warnings are stored with the completed job.

## Required Cloudflare Bindings

Configure these bindings in `apps/api/wrangler.jsonc` for deployed environments:

- `DB`: D1 database using `packages/database/migrations`.
- `DATASETS_BUCKET`: R2 bucket for JSON, JSONL, CSV, and metadata artifacts.
- `DATASET_QUEUE`: Queue producer and consumer for asynchronous dataset generation.

Replace the local placeholder D1 database ID and resource names with account-specific resources before deployment.

## Environment and Secrets

Copy `.dev.vars.example` to `.dev.vars` for local development. `KIMI_API_KEY` is optional because deterministic fallback is supported.

- `ENVIRONMENT`
- `KIMI_API_KEY` as a local variable or Wrangler secret
- `KIMI_API_BASE_URL`
- `KIMI_MODEL`
- `PUBLIC_HOLO_API_BASE_URL` for the frontend API proxy target

Never commit `.dev.vars` or production secrets.

## Local Development

```bash
pnpm install
pnpm --filter @holo/api exec wrangler types ../../worker-configuration.d.ts
pnpm --filter @holo/api dev
```

Start the Holo frontend separately:

```bash
pnpm dev:web
```

The frontend calls `https://holo-api.hackonteam.workers.dev` directly. The API allowlists the Holo web Worker and local Astro origins through CORS.

Apply D1 migrations locally when working directly with Wrangler:

```bash
pnpm exec wrangler d1 migrations apply pipa-db --local --config apps/api/wrangler.jsonc
```

## Deployment

Create or configure the D1 database, R2 bucket, and Queue, update `apps/api/wrangler.jsonc`, set the Kimi secret if needed, and deploy:

```bash
pnpm exec wrangler secret put KIMI_API_KEY --config apps/api/wrangler.jsonc
pnpm exec wrangler d1 migrations apply pipa-db --remote --config apps/api/wrangler.jsonc
pnpm exec wrangler deploy --config apps/api/wrangler.jsonc
```

Deploy the frontend Worker independently:

```bash
pnpm deploy:web
```

The frontend Worker is named `holo-web`. Astro builds `apps/web/dist/server/wrangler.json` and deploys that generated configuration.

## MVP Limitations

- Authentication and authorization are intentionally outside the MVP scope.
- The frontend is an internal operations console and does not implement authentication.
- Recommendation scoring is a deterministic baseline, not a trained production ML model.
- Kimi semantic enrichment is optional and does not rank KOCs or generate numeric metrics.
- Production resource IDs, domains, rate limiting, and account-specific observability policies must be configured per deployment.
