# Holo - All Context

Last updated: 2026-08-09

Holo is an AI-assisted SKU-KOC recommendation platform for fashion e-commerce. The MVP includes a Cloudflare Workers API and an Astro/React frontend with deterministic recommendations, reproducible synthetic data, optional Kimi semantic enrichment, D1 persistence, R2 artifacts, and Queue-backed dataset generation.

## Technology Stack

- **Runtime:** Cloudflare Workers with `nodejs_compat`.
- **Frontend:** Astro 7 with `@astrojs/cloudflare`, React 19 islands, and Wrangler Worker deployment.
- **HTTP:** Hono and `@hono/zod-openapi`.
- **Design system:** Astryx / XDS (`@astryxdesign/core`) with application-specific CSS tokens.
- **Documentation:** OpenAPI 3.1 and Scalar.
- **Validation:** Zod 4.
- **Database:** Cloudflare D1 with migration-first SQL and repository adapters.
- **Object storage:** Cloudflare R2 for dataset artifacts.
- **Async processing:** Cloudflare Queues for generation jobs.
- **LLM:** Kimi API using `kimi-k2.6` for semantic fields only.
- **Effect:** Used for external LLM/storage and asynchronous generation operations with typed errors.
- **Workspace:** pnpm 11 and Turborepo.
- **Quality:** TypeScript strict mode, Biome, Vitest, and Workers Vitest pool.

## Architectural Conventions

- Route handlers do not contain SQL or business rules.
- Application use cases receive repository and service ports through dependency injection.
- Domain models do not import Hono, Cloudflare, Zod, or Effect.
- Runtime SQL is confined to `packages/database/src/repositories`; migration SQL defines schema only.
- Product rows represent sellable SKUs and use `skuId` as their primary identifier.
- Recommendation scores are deterministic, normalized to 0-100, configurable, and explainable in Vietnamese.
- Numeric synthetic metrics are generated by seeded code, never by the LLM.
- Kimi failures use deterministic semantic fallback and are recorded as structured warnings.
- Request IDs are returned in `X-Request-ID` and included in structured logs and error responses.
- Browser API calls use the deployed Holo API directly; the API allowlists the Holo web Worker and local Astro origins through CORS.
- The frontend UI is Vietnamese-first; source identifiers remain English.

## Environment and Bindings

Required Worker bindings are `DB`, `DATASETS_BUCKET`, and `DATASET_QUEUE`. Runtime variables are `ENVIRONMENT`, `KIMI_API_BASE_URL`, and `KIMI_MODEL`. `KIMI_API_KEY` is a secret and belongs in `.dev.vars` locally or Wrangler secrets in deployed environments.

## Dataset Defaults

The default seed is `20260806`. Defaults are 200 SKUs, 80 KOCs, 200 campaigns, and 3,000 interactions. Limits are 1-500 SKUs, 1-250 KOCs, 1-1,000 campaigns, 100-20,000 interactions, and a cold-start rate from 0 to 0.5.
